# The Daily Noodle: site facts

Read this before any change that touches the whole site (names, addresses,
sections, publishing, saved progress, tracking). It is the one place these
facts live; the Claude Projects and scheduled tasks point here instead of
repeating them. Detail on sections, tracking, admin, share text and engines is
in `toolchain/site-sections-and-tracking.md`.

## Identity
- Name: **The Daily Noodle** (formerly Digi News / Digi Puzzles / Digi Games, renamed 18 Oct 2026).
- Address: **https://dailynoodle.co.uk** (GitHub Pages, deployed by the build workflow, HTTPS enforced; `www.` redirects to it). Domain registered and DNS-hosted at Cloudflare, records "DNS only".
- Repo: **alecldarlow-cell/dailynoodle** (this repo; renamed from `digi-news`). Publish to `main`.
- `alecldarlow-cell/digi-news` is now a separate, tiny **forwarding repo** for old links. Never build in it or publish to it. It must stay public with Pages on.
- Audience: about ten friends and family who compare puzzle results in a WhatsApp group. A hobby site, not a public publication.

- Every piece, puzzle and game is one HTML file in `reports/`; its desk comes from `dn:kind`, not the folder.
- Front pages share `front.css` and `front.js`; each page only sets `data-section` on `<html>`.
- **Dark mode** (18 Oct 2026): the front pages (News, Puzzles, Games, Lab, board, privacy, 404) follow the phone's light or dark setting, like the puzzle players, so moving between them doesn't flash. The dark palette is a token block at the top of `front.css` (canvas #11131A, the players' own dark; accents lifted to stay readable); each page carries a light and a dark `theme-color` meta, and `engines/finish.js` adds the dark one on puzzle pages. New colours go in as tokens, never literals, or they'll miss dark mode. Card tiles that are pictures carry their own dark version: `assets/borders-thumb.svg` and `assets/tangle-thumb.svg` hold a `prefers-color-scheme` style (an SVG shown in an `<img>` follows the page). Tangle pages still carry their tile as a `data:` URI in `dn:thumb`; `build-feed.js` points Tangle cards at the asset instead. `admin.html` is light only. News pieces follow too: `tools/news-dark.js` (run on every push and nightly, like `news-share.js`) keeps one marked block in each piece's `<head>` (`<!-- nn-dark:start … -->`) with the dark tokens, the template's few literal colours, and a small script that, in dark mode only, swaps the chart library's colour roles (`DN.colors`) and any light colour a chart spec names for its dark twin, by catching the library as it is assigned to `window.DN`. The gated piece itself is not edited; `--remove` takes the block out byte for byte. Games keep their own designs.
- Brand status: front pages, privacy, admin and the app manifest say The Daily Noodle. News pieces say **Noodle News** (masthead Noodle**News**, title "<headline> — Noodle News", byline "Noodle News data desk", production note and footer), rebranded 18 Oct 2026 across all published pieces and in the toolchain (`digi-news-house-template-v3-3-3.html`, `dn-build.py`, rubric, checklist, style guide), so new pieces are built with it. Toolchain file names and the internal `DN — Digi News visualization library` marker (which `dn-build.py` and `dn-lint.js` look for) deliberately keep the old name.
- Puzzle pages: all seven types say Noodle from 18 Oct 2026, with plain names (Alec's call): titles "<Name> — Noodle Puzzles" (Mini, Doku, Sweep, Path, Link, Tangle, Borders), home-screen names "Mini", "Doku" and so on, the DP masthead as Noodle**Puzzles** with the name as its eyebrow, back links "← Puzzles", and "Noodle Games" for Borderline. Patched with `tools/rebrand-pages.js <type>`, a literal find/replace of whole markup strings, one commit per type; `--reverse` restores the pages byte for byte, `--check` exits 1 if a page still needs it. The newest page of each type is the template for new ones, so it carries the wording forward. The engines' shared chrome (house.js) hides the old masthead on the five grid and tile types anyway. Nothing in a `<script>` or comment changes: puzzle ids, filenames, localStorage keys, the agreed share text and the `Digi Puzzles` comment markers the tools look for (e.g. `/* ---- Digi Puzzles: Mini player` in `tools/pinwheel-regen.js`) stay as they are.

## Link previews (share image)
- Every page with a link preview uses **`assets/share-card.png`** (1200 × 630, about 160 KB) as `og:image`, with `og:image:width`/`height`/`alt` and `twitter:card` `summary_large_image`, so WhatsApp shows a large banner rather than the square icon. Added 18 Oct 2026. Keep it 1200 × 630 and well under 300 KB, or WhatsApp may fall back to a small thumbnail.
- The design (the "phone ad": headline, a news front page on a phone, floating Mini and Paper Planes cards) is board D2 on Alec's "Daily Noodle share image" design canvas in claude.ai. To change it, edit there and re-export at 1200 × 630. If the file content changes, give it a new name (or add `?v=2` to the URL in the tags), because WhatsApp and Facebook cache images by URL.
- League invite links carry `&v=2` (`PREVIEW_V` in `board.html`). WhatsApp keeps the first preview it made for a URL, and an invite link never otherwise changes, so bump `PREVIEW_V` whenever the share image changes. board.html drops `v` from the address on arrival.
- Every piece, puzzle and game in `reports/` uses the same banner, set by `tools/og-tags.js` (`IMAGE`) in the workflow (18 Oct 2026). Leaderboard shares and league invites link to `board.html`, so they show it too. Per-section variants may come later: change `IMAGE` in `og-tags.js` (by `dn:kind`) and the front pages' tags.

## Publishing
- Push a file to `reports/` on `main`. `.github/workflows/build-feed.yml` then injects the tracker, patches share text, moves puzzles onto the shared engines, writes link-preview (Open Graph) tags from each file's `dn:*` metas plus the share banner (`tools/og-tags.js`), adds the Share button to every news piece (`tools/news-share.js`) and rebuilds `feed.json`. If a scheduled task pushes at the same time, the workflow rebases and retries its push.
- **The site is deployed by that workflow, not served straight from the repo** (Settings → Pages → Source: GitHub Actions). Its last steps build `_site/` with `tools/build-site.js`: site files plus `reports/` minus every forward-dated file the feed holds back. `tools/`, `toolchain/`, `.github/` and notes are never published. So a change reaches the live site only when the workflow succeeds; check Actions if something doesn't appear.
- The same workflow runs nightly around London midnight, so forward-dated files appear on their own day without a push.
- Forward-dated puzzles (answers included) are still readable in the repo itself while it is public.
- Scheduled tasks (claude.ai): **Daily news** (00:52 UTC; two news pieces, built to rubric v5: at least one pegged to an event or decision) and **Pinwheel clean-up** (02:37 London; replaces banned Mini/Doku layouts). Both clone `alecldarlow-cell/dailynoodle` and push to `main`.

## Saved progress (do not break)
- Streaks, finished puzzles and game saves live in each player's browser `localStorage` for the site's address. Keys include `noodle-board-v1` (leaderboard leagues), `digi-mini-v1`, `digi-mini-streak`, `digi-doku-v1`, `digi-doku-streak` (from 18 Oct 2026; Doku shared `digi-mini-streak` before, and its own streak is rebuilt from its saved results the first time it is read), `digi-sweep-v1`, `digi-sweep-streak`, `digi-path-v1`, `digi-path-streak` (from 18 Oct 2026; Path kept no streak before), `digi-link-v1`, `digi-link-streak`, `digi-tangle-v1`, `digi-borders-v1`, `digi-borderline-v1`. Never rename a key, a puzzle id or a puzzle's file path.
- Streak days are London calendar days in every type (Mini, Doku, Link and Sweep used the UTC date until 18 Oct 2026, so a play between midnight and 1 am BST counted for the day before). A streak save written before then carries no `tz` mark and is allowed one extra day of gap, once; the next write adds `tz:"L"`.
- Browser storage belongs to one address. Any future address change needs a handoff like the 18 Oct one: the forwarding repo packs the old address's storage into the link's `#dnmove=` fragment and `dn-track.js` merges it in on arrival without overwriting newer progress. If the new address already has its own tracker id, the old one is kept in `digi.aid.prev` (up to 5) for the leaderboard's history copy; opting out of tracking deletes it with `digi.aid`. On an iPhone, Safari, each home-screen icon and Private Browsing each keep separate storage, so the handoff only reaches the one it was opened in; Private Browsing keeps nothing between visits, so league membership doesn't stick there either.

## Players
- **Finish sheet** (18 Oct 2026): every puzzle type is moving onto one shared result screen, `engines/finish.js` + `engines/finish.css` (design approved by Alec from mocks). An engine loads it with a two-line stub at its top (a queue on `window.dnFinish` plus a `document.write` of the CSS and script) and calls `dnFinish.show({...})` once its result fields are filled, before it adds the tracker's `on`. The sheet is built inside the tracker's result box (`#winModal`, `#modal` on Path) and adopts the engine's own id'd elements, so every id `dn-track.js` reads stays in the box, filled as before; the sheet opens with class `fin-open`, never `on`, so reopening a finished puzzle shows it without logging a second finish. All seven types are on it.
- **House chrome** (18 Oct 2026): `engines/house.js` + `engines/house.css`, loaded by the same stub after `finish.js`, give the grid and tile players (Mini, Doku, Sweep, Path, Link, as each adopts it) one look: a slim bar in place of the old masthead and meta row (back to Puzzles, number, difficulty, streak, clock), a start card before a puzzle you haven't finished (rule, Play, your stats, How to play), Archivo and Instrument Serif, and a dark palette that follows the phone (`html.dn-house`, `dn-dark`). It only moves the engine's own id'd elements (`#pid`, `#pband`, `#rank`, `#timer`, `#streak`/`#streakn`) into the bar. First paint (18 Oct 2026): each engine's CSS `@import`s `finish.css` (and `house.css` on the five), so dark mode applies before any script; the page body stays hidden until house.js has built it, and the engine's own result box until finish.js has (each shows anyway after 2.5 s if its script never runs). Without this, opening a puzzle in dark mode showed a frame of the old light layout. Today's list for the Next row is cached for the day in `localStorage` key `dn-today-cache`, and the board link's room is kept, so the sheet doesn't jump when they arrive. Test: `flash:dark` records every painted frame. The sheet's faces (Archivo, Instrument Serif) are `@import`ed by `finish.css` with `display=block`, and the sheet (on the five, the whole page) waits for them, at most a second (`html.dn-fonts`, set by finish.js), so a slow font no longer re-flows the headline; test `flash:fonts`. A reopened puzzle no longer moves focus, and the sheet and start card draw no scrollbar. The Play button is `#dnPlay`, outside the tracker's play area, so a puzzle still starts on the first tap on the board. Tangle and Borders keep their own home screens, restyled in their own CSS.
- `puzzles-today.json` at the root (written by `tools/build-feed.js`, committed and deployed by the workflow) lists today's puzzles (type, id, name, path) for the sheet's "Next" row; the sheet works out what you've played from each type's save. `dn-board.js` puts "See today's board" in the sheet's `.fin-board-slot`. The Puzzles front page shows the same overall run ("You've played every day for N days", `front.js` `showRun`), worked out from the players' saves.
- Browser tests: `node tools/tests/run.js [filter]` plays real puzzles with jittered taps in headless Chromium (Playwright) and checks the result screens, share paths, saved progress and tracker reads; `tools/tests/shots.js` takes before/after screenshots. See `tools/tests/harness.js` for setup. `tools/build-registry.js` (copied in from project knowledge, 18 Oct 2026) is the registry check: `node tools/build-registry.js --check`; its 8 errors on 18 Oct are all old July–August files (known).

- **Full-screen app** (18 Oct 2026): the installed app opens full screen (`manifest.webmanifest` `display: fullscreen`), and Android brings its bars back for a moment on each page load. The pages hold the top and bottom insets and the screen height steady there (`--dn-top`, `--dn-bot`, `--dn-vh`, set by a small script inlined in each front page's `<head>` and at the top of `engines/finish.js`, only in `display-mode: fullscreen`): a new value is taken up once it has held for 0.7 s and remembered per orientation in `localStorage` key `dn-pin`. Use `var(--dn-top, env(safe-area-inset-top, 0px))` (and the bottom and height equivalents) for anything new. Test: `flash:flick`.

## Tracking and admin
- `dn-track.js` (loaded by every page) records anonymous events into the `digi` Supabase project (London). The database accepts the sections news, puzzles, games and site only; any other page (Lab, or a new one) is recorded as `site`. It also holds the domain-move import, which runs before the tracker and is independent of tracking opt-out.
- News pieces have two Share buttons (under the dateline, above the footer), added by `tools/news-share.js` in the build workflow, not by the toolchain. They open the phone's share sheet (or copy, on desktop) with the headline, first hero stat and the link tagged `?via=share`, and record `share_click` / `share_done` (props `method` native|copy, `pos` top|end).
- `page_view` carries `inst` (1 when opened from a home-screen icon, else 0) from 18 Oct 2026; earlier views have no `inst`.
- **Leaderboards** (18 Oct 2026): `board.html` shows private leagues' daily leaderboard per puzzle (pills by puzzle, day bar, share and invite, league settings). `dn-board.js` holds the league logic; `dn-track.js` loads it on every puzzle page, where it submits results for players in a league (the `dn:puzzle_end` browser event, fired whether or not visits are recorded) and adds "See today's board" to the result box. The Board pill leads the Puzzles topic row (`front.js`). When a browser is in a league, `board_backfill` copies in that browser's history: the puzzles' own saves (preferred) and its earlier `puzzle_end` events found by its tracker ids (the current `digi.aid`, plus any older one the domain-move handoff brought in as `digi.aid.prev`), which aren't stored. From 19 Oct 2026 it copies again whenever the saves hold more finished puzzles than last time or a tracker id hasn't been read (`fill` {n, aids} in `noodle-board-v1`, replacing the one-off `filled` flag); the server keeps the first result per puzzle, so a repeat copy never changes the board. History is only ever matched by ids held in that same browser, never by guessing who someone is (Alec, 19 Oct 2026). A player whose saves are still on the old github.io address gets them across by opening any old link once, in the same browser they played in. Players are identified by a separate random id in `localStorage` key `noodle-board-v1`, not the tracker's id. Data lives in the private `board` schema of the `digi` project, reached only through `public.board_*` functions; limits, word filter and the nightly `board-tidy` job are in `toolchain/sql/2026-10-18-leaderboards.sql`. The admin page's Leagues section lists leagues, can rename them and pause sign-ups. **Nothing is deleted (by choice, 18 Oct 2026):** leaving, removing a player and closing a league only hide rows (`members.left_at`, with the nickname kept in `left_nick` and replaced by a `~` placeholder so the name is free; `leagues.closed_at`). A player who rejoins gets their row and results back. The admin page can also remove, close and reopen. There is no tidy-up job, and the visit data (`public.events`) is never touched. Board events: `board_open` {from}, `board_create`, `board_join` {via}, `board_share`, `board_invite`; front pages also record `chip_click` {topic}.
- `admin.html`: magic-link sign-in. Supabase Auth allows `https://dailynoodle.co.uk/admin.html` as a redirect URL.

## Changing something site-wide
1. Update this file in the same commit as the change.
2. If a name or address changes, also check: `front.js` (`CONFIG`), `toolchain/README.md` and `toolchain/SESSION-PROTOCOL.md` (clone commands), the two scheduled tasks' prompts, Supabase Auth URLs, and the forwarding repo.
3. Keep localStorage keys, puzzle ids and file paths stable.
