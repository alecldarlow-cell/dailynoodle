# The Daily Noodle: site facts

Read this before any change that touches the whole site (names, addresses,
sections, publishing, saved progress, tracking). It is the one place these
facts live; the Claude Projects and scheduled tasks point here instead of
repeating them. Detail on sections, tracking, admin, share text and engines is
in `toolchain/site-sections-and-tracking.md`.

- **Front-page behaviour** (19 Oct 2026, site review): the list comes only from `feed.json`; if it can't load (usually no signal) the page says so with a Try again button and retries by itself when the phone is back online. (The old GitHub-API fallback is gone: it showed "No puzzles published yet" when offline and listed held-back files that 404.) The chosen topic and the card at the top of the screen are kept in `history.state` (`dnFront`), so Back from a piece or puzzle returns to the same place even when the browser didn't keep the page in its back-forward cache. Cards carry a London calendar day (Today, Yesterday, 3d ago, then the date), not hours, since items have a day, not a time. ## Publishing
- Push a file to `reports/` on `main`. `.github/workflows/build-feed.yml` then injects the tracker, patches share text, moves puzzles onto the shared engines, writes link-preview (Open Graph) tags from each file's `dn:*` metas plus the share banner (`tools/og-tags.js`), adds the Share buttons and the back-to-News link to every news piece (`tools/news-share.js`, `tools/news-nav.js`) and rebuilds `feed.json`. Since 19 Oct 2026 it then runs the full test suite on the result and deploys only if every required check passes (see Automated testing). If a scheduled task pushes at the same time, the workflow rebases, rebuilds and retests before it pushes.
- **The site is deployed by that workflow, not served straight from the repo** (Settings → Pages → Source: GitHub Actions). Its last steps build `_site/` with `tools/build-site.js`: site files plus `reports/` minus every forward-dated file the feed holds back. `tools/`, `toolchain/`, `.github/` and notes are never published. So a change reaches the live site only when the workflow succeeds; check Actions if something doesn't appear. Since the five-group test pool (20 Oct 2026) a push run usually takes about 4 minutes start to finish (3–9 minutes that morning; more if GitHub queues it), and one failing check anywhere holds back the whole site, not just the file that caused it. After deploying, the run checks the live site read-only (`npm run test:live`), so a red run can mean either "not published" or "published, but the live check failed": read it alongside the admin page's Publishing section. Time a release by the whole workflow run on GitHub, not by the test timings in its logs, which leave out setup, deployment and queueing. GitHub may cancel a queued run when a newer one arrives; the newer run builds all of `main`, so a cancelled run on its own is not a problem.
- The same workflow runs nightly around London midnight, so forward-dated files appear on their own day without a push. GitHub runs scheduled workflows late (2-3 h in Oct 2026), so today's files usually go live between 2 and 4:30 am London; the Daily news task's push often triggers a build sooner. Aim (Alec, 19 Oct 2026): reliably live by 4-5 am, not necessarily at midnight. There are eight nightly slots for that (three added 19 Oct).
- Forward-dated puzzles (answers included) are still readable in the repo itself while it is public.
- Scheduled tasks (claude.ai): **Daily news** (00:52 UTC; two news pieces, built to rubric v5: at least one pegged to an event or decision) and **Pinwheel clean-up** (02:37 London; replaces banned Mini/Doku layouts). Both clone `alecldarlow-cell/dailynoodle` and push to `main`.

## Saved progress (do not break)
- Streaks, finished puzzles and game saves live in each player's browser `localStorage` for the site's address. Keys include `noodle-board-v1` (leaderboard leagues), `digi-mini-v1`, `digi-mini-streak`, `digi-doku-v1`, `digi-doku-streak` (from 18 Oct 2026; Doku shared `digi-mini-streak` before, and its own streak is rebuilt from its saved results the first time it is read), `digi-sweep-v1`, `digi-sweep-streak`, `digi-path-v1`, `digi-path-streak` (from 18 Oct 2026; Path kept no streak before), `digi-link-v1`, `digi-link-streak`, `digi-tangle-v1`, `digi-borders-v1`, `digi-borderline-v1`, `digi-reckon-v1` (Reckon, from 20 Oct 2026: done[id] = {p points, b bullseyes, z zone per question, g guesses, secs, d}, plus `streak`, `best`, `cur` and settings), `digi-ballpark-v1` (the Ballpark game). Never rename a key, a puzzle id or a puzzle's file path.
- **Unfinished rounds:** only Tangle, Borders and Reckon keep a round you haven't finished (Borders and Reckon in a single `cur` slot); Mini, Doku, Sweep, Path and Link keep only finished results and streaks.
- **Save-failure notice** (20 Oct 2026): when the browser refuses a write (for example, storage full or blocked), the eight daily players carry on and show one quiet inline line on the result screen, with a "Try saving again" button. It covers finished results, streaks and Tangle/Borders/Reckon unfinished rounds. It never covers the board, pauses the clock, moves focus or announces itself, and appears once however many writes fail. Settings and cache writes never raise it (engines call `persist(false)` for settings). The failed data is held only in that open tab: closing or reloading it loses it. A retried result keeps its first score and original London day, and it says "Saved" only once every failed key has gone through. Out of scope: old self-contained archive players, the Games collection, Borders' atlas collection, and league/board submissions. Code: `dn-core.js` (`saveIssues`, `onSaveChange`, `retrySaves`) and `engines/finish.js`/`.css`; tests `tools/tests/browser/save-notice.spec.js`, `save-history.spec.js`, `tools/tests/unit/core.test.js`. Backup and cross-device sync are still not built.
- Streak days are London calendar days in every type (Mini, Doku, Link and Sweep used the UTC date until 18 Oct 2026, so a play between midnight and 1 am BST counted for the day before). A streak save written before then carries no `tz` mark and is allowed one extra day of gap, once; the next write adds `tz:"L"`.
- Completed-result dates (`done[id].d`) also use London days (19 Oct 2026 review fix), including archived full Mini/Sweep pages and new done-state patches. Mixing UTC completion days with London streak days could turn one play at 00:30 BST into a two-day overall run. Existing result records are kept as saved; their original time of day is not available to safely redate them.
- Browser storage belongs to one address. Any future address change needs a handoff like the 18 Oct one: the forwarding repo packs the old address's storage into the link's `#dnmove=` fragment and `dn-track.js` merges it in on arrival without overwriting newer progress. If the new address already has its own tracker id, the old one is kept in `digi.aid.prev` (up to 5) for the leaderboard's history copy; opting out of tracking deletes it with `digi.aid`. On an iPhone, Safari, each home-screen icon and Private Browsing each keep separate storage, so the handoff only reaches the one it was opened in; Private Browsing keeps nothing between visits, so league membership doesn't stick there either.
